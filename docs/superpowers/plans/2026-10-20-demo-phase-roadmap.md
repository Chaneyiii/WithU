## 规划边界

- 本文是阶段划分，不替代原计划的 GUI 设计要求、T01–T17 完成记录或产品规格。
- Phase 表示本轮收尾阶段，D1–D9 表示能力领域，T01–T17 表示执行任务；Phase 不等同历史 P0–P3。
- 保持 T02 → T17 顺序；一次推进一个 T 项，共享界面、IPC、server 路由和版本文件顺序集成。
- 执行授权与状态：2026-10-20 用户授权执行 Phase 0 与 Phase 1；Phase 2 于 2026-10-25 完成实机验证并经用户视觉验收。**Phase 0–2 已收口（v0.3.1go3，2026-10-25），GUI 自此冻结**（方向文档 §5 v3.8：后续阶段不做 GUI 结构性改动）；本文为 Phase 3–7 的执行依据（2026-10-25 更新版）。
- Demo 的范围和排除项沿用原计划及 Demo 范围文档，不扩展到正式版 Cowork、3D、本地模型安装管理或独立 ASR/TTS 开发线。
- 开发验证沿用隔离数据和本地模拟端点；模拟通过与真实服务、真机验收分别记录。
- 每个 T 项先核对已有实现和证据，确定属于“开发补齐”“集成修复”还是“验收补证”，再估工期。

## 全阶段硬性要求：参考项目、质量与安全（2026-10-25 增补）

### 参考项目必须实际查阅

方向文档 §8.4 与附录 B.16/B.24 建立了工程问题的权威查阅顺序与「板块—仓库背书矩阵」：先官方文档（Claude / OpenAI / MCP），再 Withu 既有决议，最后高质量参考仓库（OpenMuse、Codex、ZCode、DeepTutor、jcode、Kilo、WeKnora、OpenViking、AliSQL、BqLog 等）；各板块对应哪些仓库见矩阵行。

- **执行偏差记录**：Phase 1–2（GUI 收口）实施期间未按该矩阵查阅参考项目，属于执行偏差，方向文档的调研投入未被使用。自 Phase 3 起这是每个 T 项的**硬性门槛**，不是可选参考。
- **门槛**：动手实现前，先按矩阵定位本 T 项对应行的参考仓库与官方文档，读对应实现（会话/任务/工具状态组织、runtime 生命周期、并发治理、sandbox、富结果卡片、记忆派生索引、日志组织等），再写代码；实现与参考不一致处必须在任务记录中说明理由，不允许静默偏离。
- **记录**：每个 T 项的完成记录新增「参考对照」栏——参考了哪些文档/仓库的哪些模块，采用了什么、因什么条件不采用什么；没有证据的「参考过」按未参考处理。
- 各 Phase 的具体映射见下方各阶段「参考与边界」。

### 质量要求

- 每步完成后必须有 v3 自己的回放与验收，不引用 v1/v2 通过记录；四层记录（源码实现 / 自动化验证 / 真实服务验证 / 真机与人工验收）不可互相替代。
- 提交前执行仓库既有检查：`npm.cmd run check`、`npm.cmd run build:contracts`、`cargo test --workspace`、`cargo build --workspace --release`；涉及界面/打包的改动另跑 `package:windows` 与 `--withu-check` 打包自检。
- 每个 T 项动手前先分类：开发补齐 / 集成修复 / 验收补证；「已打包」不能抵消未完成的产品验收。
- 失败路径是一等公民：澄清、拒绝、取消、超时、崩溃恢复都要有真实断言，不允许只验证 happy path；模拟验证与真实服务/真机验证分别记录。
- 冻结后发生代码或包内容变化，重新核对受影响验证、包哈希与源码匹配。

### 安全要求

- **凭据**：API Key 等只存 Windows 凭据管理器；日志、审计、导出、诊断一律不得出现明文凭据（导出脱敏断言已有，延续）。
- **沙箱与隔离**：renderer 维持 contextIsolation + sandbox、无 Node 暴露（`--withu-check` 已断言）；MCP App 在隔离 iframe 内按 CSP 与资源域限制加载；浏览器抽屉 webview 使用独立 partition，不与主 GUI 共享会话。
- **审批与副作用**：高影响动作默认 Manual、逐动作显式 Allow；拒绝/取消零副作用；重复确认不重复执行（版本 CAS）；第三方页面自己画的确认按钮不构成 Withu 审批。
- **删除与隐私**：记忆/数据删除走墓碑语义，删除后候选、缓存与派生索引不得复活；未经授权不保存；Live 只保存时长摘要，不新增原始音频或逐句转写落盘。
- **网络边界**：外链走域名白名单（openExternal 拦截已有）；检索与连接器仅使用用户已配置授权的服务，不静默切换 provider；未配置时如实报告。
- **依赖与打包**：参考仓库代码（如 AliSQL GPLv2）不得因参考而进入默认依赖，许可证与安全评估通过前不引入；打包产物不含凭据，交付记录源码提交与包 SHA-256 对应。
- 每阶段验收清单必须包含上述相关项；安全项缺失按该阶段未通过处理。
