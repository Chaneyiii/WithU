## 2. Phase 6（T16）：统一多入口体验和运行边界

roadmap 三条线并行推进，顺序建议：文字/语音 → MCP App → 主动性（主动性依赖前两者的授权与结果机制稳定）。

### 2.1 T16-A 文字/语音同权（参考：B.6 语音主链路、B.7 流式回合；对照 OpenMuse 富结果、ZCode workspace/工具块）

- [ ] 同一动作双入口：文字发起与语音发起的提醒/草稿/检索走同一 `prepare → allow → execute` 链、同一版本 CAS、同一结果卡片组件；断言两边产生的审计与卡片字段一致。
- [ ] 打断：语音回合进行中用户插话 → 当前回合取消、半成品副作用不落库；文字侧发送中取消行为一致。
- [ ] 取消与清理：通话结束/切换会话时音频会话、监听、临时文件清理幂等；重复取消不报错。
- [ ] 不重复副作用：同一句话经语音说出后又在文字里重复，不产生两条提醒（幂等键覆盖双入口）。
- [ ] Live 边界：只保存时长摘要，不新增原始音频或逐句转写落盘（回归断言）。
- [ ] 记录「参考对照」：OpenAI Realtime 的 barge-in/turn-taking 契约采用什么、xAI 流式参考不采用什么、理由。

### 2.2 T16-B MCP App（参考：B.21.2 MCP Apps 稳定规范、app-bridge 隔离模型；Electron WebContentsView）

- [ ] 真实对话触发：标准 MCP App 在消息内 Intelligence UI 完成能力协商、资源读取、握手、工具结果、动作回传、teardown 全生命周期（D7 契约已有，本轮验真实链路）。
- [ ] 授权：App 内动作与聊天动作同走 R07 审批；第三方页面自绘确认按钮不构成 Withu 审批（安全基线）。
- [ ] 隔离：App 在隔离 iframe 按 CSP 与资源域加载；跨 server 工具调用、未声明域访问、读取 host bridge/密钥/记忆被阻止（负路径断言）。
- [ ] 生命周期：窗口隐藏/恢复、会话切换、应用退出时 App 资源（浏览视图、附属端口、子进程）释放。
- [ ] 媒体/语音协调：真实播放器状态驱动提示；TTS 与媒体音频不叠音；播放声音不触发用户命令或审批。
- [ ] 无 UI 能力服务：继续提供文字或原生卡片，不伪报兼容。

### 2.3 T16-C 主动性（参考：B.19 通知与定时规则、§8.3 克制策略）

- [ ] 已授权候选触发：到期提醒经真实 Windows 通知中心弹出（**真机硬门槛**，D8 遗留归并于此），点击通知回到对应会话/卡片。
- [ ] 门控：优先级排序、安静时段（Settings 已有配置实机生效）、暂停、不追发（同一事项只提醒一次直至用户处理）。
- [ ] 权限边界：Windows 通知权限被系统关闭时的降级呈现（应用内胶囊仍可用，如实标注）；Focus Assist 开启时不弹窗（真机记录）。
- [ ] 运行边界：窗口隐藏时主动性照常（server 独立进程）；**应用完全退出后不产生任何新主动行为**（shutdown handshake 回归）。
- [ ] 语音与通知协调：通话中不弹打扰性通知（按优先级静默或延后）。

### 2.4 Phase 6 验收门槛（roadmap 原文要点 + 记录要求）

- 文字与语音进入同一动作语义一致；禁止绕过审批。
- **Windows 通知中心、Focus Assist、真实声学（麦克风/扬声器）、第三方服务分别记录真机结果；模拟证据不替代。**
- 四层记录（源码实现 / 自动化验证 / 真实服务验证 / 真机与人工验收）逐线补齐；「参考对照」栏逐 T 项填写，无证据的「参考过」按未参考处理。
- 安全清单：凭据不落日志、MCP App 会话隔离、打断/取消幂等、通知授权规则、Live 音频边界、退出后无主动行为——任一缺失按该阶段未通过处理。

## 4. 执行纪律（沿用 roadmap 硬性要求）

1. 每个 T 项动手前先分类：开发补齐 / 集成修复 / 验收补证。
2. 动手前按背书矩阵查阅对应参考仓库/官方文档，记录「参考对照」。
3. 失败路径一等公民：打断、取消、拒绝、超时、崩溃恢复都要真实断言。
4. 提交前跑仓库既有检查；冻结后任何变化重新核对受影响验证与哈希。
5. GUI 已冻结：不做结构性改动；确需新界面先经用户决策并更新方向文档 §5。
